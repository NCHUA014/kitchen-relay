# Handover Study Design

## Purpose

Compare how different handover-document designs affect cultural transmission,
downstream play, and adaptation to environmental change in Kitchen Relay.

Run one handover condition for an entire multi-stage relay. Use fresh agents,
the same stage sequence, and comparable seeds across repeated runs.

## Conditions

1. **Living document — current design**
   - One shared notepad.
   - Agents can edit and replace the latest document.
   - The next agent sees the current version only.
   - Database revisions remain researcher-only evidence.

2. **Freeform relay note**
   - Each agent submits an uneditable note.
   - The next agent sees only the immediately previous agent's note.
   - Tests compression, accuracy, and relay-style cultural transmission.

3. **Freeform archive**
   - Each agent submits an uneditable note.
   - The next agent sees every previous note.
   - Tests whether historical access helps or produces overload and conflicts.

4. **Structured archive**
   - Each stage creates an uneditable note using a shared template.
   - The next agent sees every previous stage note.
   - Tests whether structured organisational memory is easier to use.

5. **Structured relay note**
   - Each stage creates an uneditable templated note.
   - The next agent sees only the previous note.
   - Tests whether a concise standard handover is sufficient.

## Structured handover template

```text
## Stage [number] handover — [agent]

### Confirmed discoveries
- Verified recipes, preparation rules, customer feedback, and map facts.

### Changes / regressions
- What differs from the earlier stage.
- Which old routes or macros are unsafe, and why.

### Useful macros
- Shortcut:
- Name and intent:
- Exact sequence:
- Preconditions: start location, held item, route/landmark.
- Expected result:
- Failure condition:

### Next agent: test first
- The most important first action or fact to verify.
```

## Handover-mode concept

During the final consolidation period:

- Food tickets stop and no new tickets generate.
- The kitchen remains observable as reference.
- The agent focuses on Notes and Macros rather than ticket delivery.
- A private turn review may show the current agent its own serves, failed serves,
  customer feedback, macro changes, and ReAct summaries. It does not write the
  shared handover automatically.
- Only saved Notes and Macros pass to the next agent.

## Evaluation rubric

Judge handovers by downstream usefulness rather than note length or raw macro
count.

| Dimension | Evidence |
| --- | --- |
| Accuracy | Claims match map, recipes, preparation rules, and macro behaviour. |
| Actionability | The next agent can make useful first actions without guessing. |
| Regression awareness | Changed layouts and unsafe prior macros are identified. |
| Macro quality | Shortcut, sequence, intent, preconditions, result, and failure condition are documented. |
| Concision | Little repetition, stale information, or irrelevant diary content. |
| Downstream effect | Faster first successful serve, fewer invalid actions, useful macro reuse/revision, and better completed/missed results. |

## Suggested first comparison

Begin with three manageable conditions:

1. Living document (current design).
2. Uneditable freeform archive.
3. Uneditable structured archive.

Add the previous-note-only relay variants after establishing this baseline.
